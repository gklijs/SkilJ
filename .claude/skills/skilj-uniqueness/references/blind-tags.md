# A unique, erasable email address, end to end

This is the shape `skilj/tests/blind_tags.rs` tests, written as an
application module would. Read that test file for the exact, compiling
version - or `skilj-demo/tests/customers.skilj.toml` and
`tests/customers.rs` for the same bounded context generated by
`skilj-codegen`.

## The module

```rust
use schemars::JsonSchema;
use serde::{Deserialize, Serialize};
use skilj::{auto_register, normalize, BlindErasure, BlindTag, CommandType, EventType};
use skilj_core::event_store::Event;
use skilj_core::plugin::BoundedContextEvent;
use skilj_core::shared::{CommandDecision, EventSpec, QueryItemMapping, SensitiveField, TagMapping};

pub const BOUNDED_CONTEXT: &str = "crm";

// 1. The constraint: one per tag key.
pub struct CustomerEmail;

#[auto_register(BOUNDED_CONTEXT)]
impl BlindTag for CustomerEmail {
    const TAG_KEY: &'static str = "email";
    // Bump only together with a change to `normalize` - and know that
    // startup refuses a bump against a stored constraint.
    const NORMALIZER_VERSION: u32 = 1;
    const ERASURE: BlindErasure = BlindErasure::with_subject("customer");
    fn normalize(value: &str) -> String {
        normalize::email(value)
    }
}

// 2. Shared mapping helpers, so every type maps the key the same way.
fn customer() -> TagMapping {
    TagMapping::new("customer", "customer_id")
}
fn email(field: &str) -> TagMapping {
    TagMapping::blind::<CustomerEmail>(field)
}
fn encrypted(field: &str) -> SensitiveField {
    SensitiveField::new(field, "customer", "customer_id")
}

// 3. Claims and releases.
#[derive(Debug, Serialize, Deserialize, JsonSchema)]
pub struct EmailPayload {
    pub customer_id: String,
    pub email: String,
}

pub struct EmailClaimed;

#[auto_register(BOUNDED_CONTEXT)]
impl EventType for EmailClaimed {
    type Payload = EmailPayload;
    const NAME: &'static str = "EmailClaimed";
    fn tag_mappings() -> Vec<TagMapping> {
        vec![customer(), email("email")] // `customer`: the subject_tag erasure needs
    }
    fn sensitive_fields() -> Vec<SensitiveField> {
        vec![encrypted("email")]
    }
}

pub struct EmailReleased; // identical shape, NAME = "EmailReleased"

// 4. The commands. Only *which* events matched matters to decide().
pub enum CustomerEvent {
    Claimed,
    Released,
}

impl BoundedContextEvent for CustomerEvent {
    fn try_from_event(event: &Event) -> Option<Result<Self, serde_json::Error>> {
        match event.event_type.name.as_str() {
            "EmailClaimed" => Some(Ok(CustomerEvent::Claimed)),
            "EmailReleased" => Some(Ok(CustomerEvent::Released)),
            _ => None,
        }
    }
}

fn latest_claim_or_release(field: &str) -> Vec<QueryItemMapping> {
    vec![QueryItemMapping::types(&["EmailClaimed", "EmailReleased"])
        .tagged(vec![email(field)])
        .latest()]
}

pub struct RegisterCustomer;

#[auto_register(BOUNDED_CONTEXT)]
impl CommandType for RegisterCustomer {
    type Payload = EmailPayload;
    type Event = CustomerEvent;
    const NAME: &'static str = "RegisterCustomer";
    fn tag_mappings() -> Vec<TagMapping> {
        vec![customer(), email("email")]
    }
    fn sensitive_fields() -> Vec<SensitiveField> {
        vec![encrypted("email")] // the command row stores the payload too
    }
    fn consistency_query() -> Vec<QueryItemMapping> {
        latest_claim_or_release("email")
    }
    fn decide(payload: &Self::Payload, events: &[Self::Event]) -> CommandDecision {
        if matches!(events.last(), Some(CustomerEvent::Claimed)) {
            return CommandDecision::Rejected {
                reason: "this email address is taken".into(),
                kind: "email_taken".into(),
            };
        }
        CommandDecision::Accepted {
            events: vec![EventSpec {
                event_type: "EmailClaimed".into(),
                payload: serde_json::to_value(payload).unwrap(),
            }],
        }
    }
}
```

`ChangeEmail { customer_id, old_email, email }` has the same query on
`email`, encrypts both address fields, and emits `EmailReleased` for
`old_email` and `EmailClaimed` for `email` in one decision - so the old
address is free and the new one taken atomically.

## Why each piece is there

- **The command tags the value too.** The command row stores its
  consistency tags and query; with a blind mapping both hold the hash, never
  the address, and erasure removes them with the events' tags.
- **The command encrypts the field too.** Its payload is stored as well.
- **`customer` is a plain tag on every type with the blind key.** Erasure
  finds the forgotten subject's events and commands by that tag
  (`subject_tag`), without decrypting anything. `build()` refuses a type
  that maps the blind key without it.
- **Claims and releases, not a status flag.** The query asks for the
  latest event of either type carrying the hash; an append-only log has
  no "delete the claim".
- **`.latest()`.** Only the last claim-or-release matters, and only events
  of those types under that tag conflict with the command - not every
  event of the customer.

## What happens on `forgetSubject("crm", "customer", "c-42")`

With `WithSubject`, in one transaction before the key is destroyed: every
event whose tags contain `customer = c-42` loses its `email` tag (in
`events.tags` and `event_tags`), every command with that tag loses it from
`consistency_tags` and its query items, and the registrations generation is
bumped so every instance's event cache refills instead of serving the old
tags. The next `RegisterCustomer` with that address finds no claim and is
accepted. Another customer's claim of a different address is untouched.

With `Keep`, nothing happens to the tags: the payloads are shredded, the
hash stays, and the address stays taken.

## Testing it

`skilj-test-fixture` exercises `decide()` alone, and there tags don't
exist - feed it the events the query would select (`Claimed` or not).
Test the hashing, the race and the erasure against Postgres the way
`skilj/tests/blind_tags.rs` does: a `Skilj` built with the `BlindTag`, a
`blind_index_key` and an `encryption_master_key`, commands submitted
through `db::decide_and_submit_command`, and
`db::forget_subject_in_blind_tags` for the erasure (what the
`forgetSubject` mutation runs before destroying the key).
